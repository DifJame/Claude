# Premium Design Review

Use this skill to review or improve the visual concept of a page, block, mockup, screenshot, or landing structure.

## Core visual direction

Default style for Moscow-city.online and related service pages:

- premium business / luxury real estate
- black, platinum, dark vanilla palette
- calm, expensive, spacious composition
- strong hierarchy, clear sections, readable typography
- minimal visual noise
- no cheap gradients
- no neon-blue digital overload
- no overloaded cards or random icons
- no generic stock-startup style

Preferred colors:

- black: `#000000`
- platinum: `#E5E5E5`
- dark vanilla / warm accent: `#DDC1A6`

## What to review

Check:

1. First-screen clarity: does the visitor instantly understand the offer?
2. Premium impression: does it feel expensive, calm, and trustworthy?
3. CTA visibility: is the next action obvious without shouting?
4. Section order: is the strongest commercial argument high enough?
5. Visual hierarchy: are title, subtitle, benefits, proof, and CTA clearly separated?
6. Density: remove blocks that feel like decoration rather than conversion.
7. Mobile layout: is the page readable and convincing on a phone?
8. Forms: are forms short, contextual, and tied to the service?
9. Trust: are proof, process, objects, numbers, or examples visible?
10. Consistency: do colors, buttons, cards, spacing, and typography feel like one brand?

## Output format

Respond in Russian unless the user asks otherwise.

Use this structure:

1. `Что уже хорошо`
2. `Что удешевляет страницу`
3. `Что мешает заявке`
4. `Что поднять выше`
5. `Что упростить`
6. `Какие блоки добавить / убрать`
7. `Точные правки для дизайна`
8. `Приоритет: что сделать первым`

Be direct. Avoid generic praise. Give practical changes that can be turned into a Claude Code task.

## Moscow-city.online safety note

When the review concerns advertising pages:

- active test page: `/reklama-v-moskva-siti-test/`
- production page must not be changed unless the user explicitly confirms: `/reklama-v-moskva-siti/`

Do not suggest large rewrites when a minimal UX patch would solve the problem.
